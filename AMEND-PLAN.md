# Amend mode — plan

## Goal

Modify an existing book without throwing away the work. Workdir is the source of
truth: `outline.json` + `ch-NN.md` + `options.json` + `cover.png`. Amend is just
structured edits to those files followed by reassembly.

```
epubgen amend <workdir|epub> rewrite 5 --instruction "make this concise"
epubgen amend <workdir|epub> insert --after 3 --title "Why measure" --hint "..."
epubgen amend <workdir|epub> remove 7
epubgen amend <workdir|epub> reorder 5 8        # move ch 5 to position 8
epubgen amend <workdir|epub> retitle --title "..." [--subtitle "..."]
epubgen amend <workdir|epub> recover            # regen cover
epubgen amend <workdir|epub> rebuild            # reassemble epub from current files
```

`amend` always ends with reassembly (renders missing figures, rebuilds
`book.opf` / TOC / epub). `--no-rebuild` writes the workdir but skips assembly
so the user can chain edits.

## Operations

### `rewrite N`
Regenerate a single chapter.
- Delete `ch-NN.md` (atomic move to `ch-NN.md.bak-<ts>`).
- Optional `--instruction TEXT` appended to the chapter prompt as a steering
  clause ("Additional steering from the user: ...").
- Optional `--source PATH` (repeatable) — temporarily inject extra sources for
  this chapter only; do not modify global `source_digest`.
- Reuses cached prefix → cheap.

### `edit N`
Open `ch-NN.md` in `$EDITOR` ($VISUAL fallback). Pure manual edit. After save,
just rebuild. No model call.

### `insert --after N | --before N | --at-end`
Append a new chapter to the outline + generate it.
- Mutate `outline.json`: assign `number = N+1`, renumber subsequent chapters,
  rename `ch-NN.md` files in reverse order to avoid clobbering.
- New chapter spec generated by a small "expand-one-chapter" model call seeded
  with `--title`, `--synopsis`, `--hint`, full outline as cached context.
  Fallback: skip the expand call when user passes a complete spec via JSON
  (`--spec FILE`).
- Generate the chapter with `generate_chapter`.

### `remove N`
- `ch-NN.md` → `.archive/ch-NN-<ts>.md`.
- Drop chapter from `outline.json`.
- Renumber chapters above N (rename files, edit outline).

### `reorder FROM TO`
- Pure rename + outline edit. No model call.

### `retitle / resubtitle`
- Edit `outline.json` only.

### `recover`
- Delete `cover.png` / `cover.svg`. Run `generate_cover`. Optionally accept
  `--cover-prompt`.

### `rebuild`
- No mutations. Just call the diagram renderer + `assemble`.
  Use case: user hand-edited `ch-NN.md` and wants the epub refreshed.

### `add-source PATH...` / `remove-source NAME`
- Edit `options.json` `source_digest`. Doesn't regenerate anything by itself —
  pair with `rewrite` for the chapters that should reflect the new sources.
  Prints which chapters reference content the source might affect.

## Renumbering invariant

After every mutation, this must hold:
- `outline.chapters[i].number == i + 1` for all i.
- `ch-NN.md` exists for every chapter, where NN matches `chapters[i].number`.
- No orphan `ch-*.md` files (unrecognized numbers go to `.archive/`).

A single `_renormalize(workdir, outline)` helper enforces this after any
insert/remove/reorder. Idempotent. Tested directly.

## Backups

Every destructive op moves the prior file into `<workdir>/.archive/` with a
timestamp suffix. No git, no in-place delete. `epubgen amend ... --no-backup`
opt-out for power users; default keeps backups.

## CLI surface

`epubgen amend` is a Typer sub-app. Each operation is a sub-subcommand so help
text is discoverable:

```
epubgen amend rewrite     <workdir> N [--instruction] [--source]
epubgen amend insert      <workdir> [--after N | --before N | --at-end] --title ... [--hint] [--spec FILE]
epubgen amend remove      <workdir> N
epubgen amend reorder     <workdir> FROM TO
epubgen amend retitle     <workdir> --title ... [--subtitle ...]
epubgen amend recover     <workdir> [--cover-prompt ...]
epubgen amend rebuild     <workdir>
epubgen amend edit        <workdir> N
epubgen amend add-source  <workdir> PATH...
```

`<workdir>` accepts the same flexible argument as `resume` (.epub path, work
dir, or directory to search).

## Wizard integration (optional, second pass)

`epubgen wizard` gains a "Modify an existing book" entry that detects
candidate workdirs in CWD, lists them with their titles, then drops into a
menu of the operations above. Each operation reuses the same underlying
functions as the CLI commands.

## What we don't do (yet)

- **Diff-style edits** — `epubgen amend patch ch-5.md` with a model-driven
  surgical edit. Defer; manual `edit` covers the use case.
- **Style switch on an existing book** — would require regenerating every
  chapter. Out of scope; the user can `epubgen generate` fresh.
- **Versioning / branching** — workdir is single-state. Backups are flat.

## Implementation order

1. `amend.py` module: pure outline+file mutators (`renumber`, `rename_chapter_file`,
   `archive`, `_renormalize`). Unit-tested against a fake workdir, no API calls.
2. `epubgen amend rebuild` — easiest, validates that the existing assemble path
   works on a workdir without going through `pipeline.run`.
3. `epubgen amend edit / retitle / reorder / remove / recover` — no model calls.
4. `epubgen amend rewrite` — single chapter regen with steering.
5. `epubgen amend insert` — outline expansion + generate.
6. `epubgen amend add-source` — opens the question of partial-rebuild scope;
   keep simple (just edits the digest, prints affected chapters, suggests
   `rewrite`).
7. Wizard entry point.

## Open questions

- **Outline drift on rewrite.** If the rewritten chapter contradicts adjacent
  chapters' synopses, do nothing or warn? Proposal: warn only, don't auto-fix.
- **Source per-chapter scope.** The proposed `--source` on `rewrite` injects
  ad-hoc sources without persisting them. Alternative: require the user to
  `add-source` first. Proposal: ad-hoc is fine, log a notice.
- **Mid-book insert and outline cohesion.** `insert` doesn't re-run the outline
  generator; the inserted chapter may not fit the original arc. Acceptable
  tradeoff — the user is opting in by choosing position + title.
