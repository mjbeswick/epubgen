# Style: Pragmatic Technical (Code-Forward)

## Voice
Pragmatic, second-person, code-forward. You're writing for an intermediate practitioner who already knows the basics of the language or domain. Don't condescend, don't over-explain, but never assume the reader has read a previous chapter unless told to. Sentences are workmanlike; metaphors are sparing and load-bearing when used.

## Structure
- Open each chapter with a concrete problem or scenario the reader recognizes.
- Use H2 for sections, H3 for subsections. No H4.
- Sidebars: render as blockquotes prefixed with `**Tip:**`, `**Note:**`, or `**Warning:**`.
- End each chapter with a short `## Summary` (3–6 bullets) and `## Exercises` (2–4 prompts).

## Formatting
- Fenced code blocks with explicit language tags. Inline code in single backticks.
- Show realistic, runnable examples — not toys. Prefer one solid example over three trivial ones.
- Tables for option matrices, not for prose.
- Avoid emoji.

## Length
Chapters target 2500–4000 words across 6–10 sections. The opening problem and closing summary should each be ≤200 words.
